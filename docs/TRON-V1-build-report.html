How the UI survived the swap

Twenty-five screens called Firestore directly. Rewriting them all was the obvious path and the wrong one — it would have meant rebuilding the exact thing you asked to keep.

Instead, src/lib/tron/firestore.ts exposes the same function names those screens already used — collection, query, where, onSnapshot, addDoc, serverTimestamp, increment — and routes every one of them to SQLite instead. The screens' imports changed by one line each. Their logic did not change at all.

Memory, and only when you say so

These four phrases are parsed by rule, not by the model, so they behave the same every time and never depend on how the model is feeling.

TRON, remember the spare key is under the blue pot stores it
TRON, what do you remember about the spare key? reads it back
TRON, forget the spare key deletes it
TRON, what do you remember? lists everything

Anything stored is offered back to the model as context when you ask a related question. Retrieval is automatic; storing never is. That's the V2 conversation.

Your next four steps

The code is on your Mac now. These are the parts that need you at a keyboard.

  1. Clear out the dead files

    The old firebase.ts and gemini.ts are still sitting in your folder, and the build fails while they're there. This removes them and files the design mockups under docs/.

    Terminal — Mac
    $ cd ~/Downloads/TRON-main
$ bash scripts/cleanup-v1.sh

  2. Set your passphrase and run it

    TRON_PASSPHRASE is the only thing standing between your data and anyone on the network. Make it long.

    Terminal — Mac
    $ cp .env.example .env.local
$ nano .env.local          # set TRON_PASSPHRASE
$ npm install && npm run build
$ npm run tron -- start

→ http://localhost:3000

  3. Push to GitHub, pull onto the Redmi

    The repo is the source of truth. On the phone, one script installs dependencies, builds, installs the tron command, and writes the boot hook.

    Termux — Redmi
    $ pkg install nodejs-lts git
$ git clone <your-repo> tron && cd tron
$ bash scripts/install-termux.sh

  4. Make it survive reboots

    The boot script is written, but Android has to be told to honour it: install Termux:Boot from F-Droid, open it once so the permission is granted, then turn off battery optimisation for both Termux and Termux:Boot. Skip that last part and Android will kill TRON overnight.

Reaching it from outside the house

At home

Open http://<redmi-ip>:3000. Add that address to TRON_ALLOWED_ORIGINS first or server actions get refused.

Away

Tailscale on the Redmi and the iPhone, same tailnet. Do not port-forward 3000 — the tunnel is the only door, the passphrase is the second.

Deliberately left out

All of this is V2 and V3. V1's job was to make the core work end to end without the cloud.

  • web search
  • weather
  • news
  • voice capture
  • autonomous agents
  • RAG / embeddings
  • automatic memory
  • multi-user accounts
  • push notifications
